## 샘플 하나에서 소리 전체로

앞에서 만든 `saturate()` 함수는 샘플 하나를 입력받아 처리된 샘플 하나를 반환한다.

```js
function saturate(input, drive) {
  const driven = input * drive;
  return Math.tanh(driven);
}
```

하지만 실제 소리는 하나의 샘플로 이루어져 있지 않다.

1초 동안 녹음된 소리의 Sample Rate가 44.1kHz라면 그 안에는 44,100개의 샘플이 들어 있다. 각 샘플은 해당 순간의 신호 크기를 숫자로 저장한다.

```js
const samples = [
  0.02,
  0.18,
  0.46,
  0.81,
  0.43,
  0.1,
  -0.25,
  -0.72,
];
```

새츄레이션을 소리 전체에 적용하려면 배열에 들어 있는 샘플을 하나씩 꺼내 `saturate()` 함수에 넣어야 한다.

JavaScript에서는 `map()`으로 이 과정을 표현할 수 있다.

```js
function processSamples(samples, drive) {
  return samples.map((sample) => saturate(sample, drive));
}
```

`map()`은 배열 안의 값을 차례로 꺼내 함수에 전달하고, 함수가 반환한 값으로 새로운 배열을 만든다.

```text
입력 샘플 배열
      ↓
샘플을 하나씩 꺼냄
      ↓
saturate()에 전달
      ↓
처리된 샘플로 새 배열 생성
```

앞에서 사용한 샘플에 `drive` 값을 2로 적용해보자.

```js
const inputSamples = [
  0.02,
  0.18,
  0.46,
  0.81,
  0.43,
  0.1,
  -0.25,
  -0.72,
];

const outputSamples = processSamples(inputSamples, 2);

console.log(outputSamples);
```

결과를 소수점 셋째 자리까지 정리하면 다음과 같다.

```text
입력
0.02, 0.18, 0.46, 0.81, 0.43, 0.10, -0.25, -0.72

출력
0.04, 0.345, 0.726, 0.925, 0.696, 0.197, -0.462, -0.894
```

입력값 `0.46`은 `0.726`이 되었고, 입력값 `0.81`은 `0.925`가 되었다.

새츄레이션이 큰 값을 누르는 처리라면 출력값이 원래 입력보다 작아져야 하는 것 아닐까?

이 결과를 이해하려면 `drive`가 먼저 무엇을 하는지 봐야 한다.

## Drive는 입력을 먼저 키운다

`saturate()` 함수의 첫 줄은 입력값과 Drive를 곱한다.

```js
const driven = input * drive;
```

입력값이 `0.5`이고 Drive가 2라면 `tanh`에 들어가는 값은 1이 된다.

```text
input = 0.5
drive = 2

0.5 × 2 = 1
Math.tanh(1) = 약 0.762
```

출력값 `0.762`는 원래 입력인 `0.5`보다 크다. 하지만 Drive만 적용한 `1`보다는 작다.

```text
원래 입력       0.5
Drive 적용      1
최종 출력       0.762
```

새츄레이션의 핵심은 출력값이 항상 원래 입력보다 작아지는 데 있지 않다.

입력을 Drive로 키우더라도 출력이 같은 비율로 계속 증가하지 않는 것이 핵심이다. 입력이 커질수록 `tanh` 곡선이 완만해지고 출력의 증가 폭은 줄어든다.

다른 값도 비교해보자.

```text
input    drive    driven    output

0.1        2       0.2       0.197
0.5        2       1.0       0.762
0.8        2       1.6       0.922
1.0        2       2.0       0.964
```

`driven` 값은 `0.2`, `1.0`, `1.6`, `2.0`으로 계속 커진다.

반면 `tanh`를 지난 출력값은 `0.197`, `0.762`, `0.922`, `0.964`가 된다. 입력은 계속 커지지만 출력은 1에 가까워질수록 증가 폭이 줄어든다.

```text
작은 입력
→ 입력과 출력이 비교적 비슷함

큰 입력
→ 출력의 증가 폭이 줄어듦

매우 큰 입력
→ 출력이 1에 가까워짐
```

음수도 같은 방식으로 처리된다.

```text
Math.tanh(2)  = 약  0.964
Math.tanh(-2) = 약 -0.964
```

양수와 음수의 큰 값이 모두 완만하게 제한되면서 파형의 위아래 모양이 달라진다.

## 실제 플러그인은 짧은 묶음으로 처리한다

위의 JavaScript 코드는 동작 원리를 확인하기 위해 여러 샘플을 하나의 배열에 담았다.

실제 플러그인은 곡 전체를 한 번에 전달받지 않는다. Cubase는 재생 중인 소리를 짧은 샘플 묶음으로 나누어 플러그인에 계속 전달한다. 이런 샘플 묶음을 `오디오 버퍼`라고 한다.

```text
Cubase가 오디오 버퍼를 전달
          ↓
각 샘플에 saturate() 적용
          ↓
처리된 오디오 버퍼를 반환
          ↓
다음 오디오 버퍼 처리
```

플러그인은 이 작업을 재생이 끝날 때까지 반복한다.

결국 새츄레이션 플러그인이 하는 일은 복잡하지 않다.

```text
샘플을 받는다
→ Drive를 곱한다
→ 비선형 함수에 넣는다
→ 처리한 샘플을 돌려준다
```

이 과정이 짧은 시간 동안 수많은 샘플에 반복되면서 파형 전체의 모양과 소리가 달라진다.

하지만 아직 해결하지 않은 문제가 있다.

Drive를 높이면 새츄레이션이 강해지는 동시에 전체 음량도 커진다. 처리 전보다 소리가 커지면 실제로 음색이 좋아진 것인지, 단순히 음량 때문에 더 좋아 보이는 것인지 구분하기 어렵다.
